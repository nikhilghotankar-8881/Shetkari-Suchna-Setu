# Internationalisation (Marathi / English)

The farmers in the pilot are in rural Maharashtra, so **Marathi is the primary language** and English is secondary. Hindi can be added later.

## Libraries

- `i18next`
- `react-i18next`
- Fonts: `@fontsource/noto-sans-devanagari` for Marathi and Hindi

## Setup

`src/i18n/index.ts`
```ts
import i18n from "i18next";
import { initReactI18next } from "react-i18next";
import en from "./locales/en.json";
import mr from "./locales/mr.json";

const saved = (() => {
  try {
    return localStorage.getItem("lang");
  } catch {
    return null;
  }
})();

i18n.use(initReactI18next).init({
  resources: { en: { translation: en }, mr: { translation: mr } },
  lng: saved ?? "mr",
  fallbackLng: "en",
  interpolation: { escapeValue: false },
});

i18n.on("languageChanged", (lng) => {
  document.documentElement.lang = lng;
  try {
    localStorage.setItem("lang", lng);
  } catch {
    /* ignore */
  }
});

export default i18n;
```

Import it once in `main.tsx` (`import "./i18n";`).

## Using translations

```tsx
import { useTranslation } from "react-i18next";

const { t } = useTranslation();
<button>{t("notice.openOfficial")}</button>
```

With variables:
```tsx
t("notice.lastChecked", { date: formattedDate })
```

## Key naming

Use grouped, lowercase, dot-separated keys:

```
app.*          app name, tagline
nav.*          navigation
home.*         home page
dashboard.*    farmer dashboard
notice.*       notice fields and actions
status.*       verification statuses
prefs.*        preferences form
admin.*        admin screens
metrics.*      impact dashboard
common.*       generic buttons, loading, errors
disclaimer.*   standard disclaimers
errors.*       error messages
```

## Rules

1. **No hard-coded user-facing strings** in components. Everything goes through `t()`.
2. Every English key must have a Marathi key. Add both in the same pull request.
3. **Official scheme names, department names and notice text** come from the source. Show the original text. If the backend provides a translation, label it as a translation and keep a link to the original.
4. Do not machine-translate legal conditions or deadlines in the frontend. Show what the backend provides.
5. Format dates and numbers by locale (see below).
6. Allow for longer Marathi strings: no fixed-width buttons, avoid truncating labels.
7. Update `<html lang>` when the language changes (done in the setup above).
8. Persist the chosen language and apply the farmer's preferred language after login.

## Date and number formatting

`src/utils/date.ts`
```ts
export function formatDate(iso: string | null, lang: string): string {
  if (!iso) return "—";
  const locale = lang === "mr" ? "mr-IN" : "en-IN";
  return new Intl.DateTimeFormat(locale, {
    day: "numeric",
    month: "short",
    year: "numeric",
  }).format(new Date(iso));
}

export function formatDateTime(iso: string, lang: string): string {
  const locale = lang === "mr" ? "mr-IN" : "en-IN";
  return new Intl.DateTimeFormat(locale, {
    dateStyle: "medium",
    timeStyle: "short",
    timeZone: "Asia/Kolkata",
  }).format(new Date(iso));
}
```

Always display times in **Asia/Kolkata** (IST).
